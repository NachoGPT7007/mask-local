# 本地脱敏工具（mask-local）

法院实习材料在交给法律 AI 工作台之前的**本地**脱敏环节。把 Word / Excel / PDF 里的姓名、证件号、电话、住址、公司机构、案号替换成带框代号，原文不出本机。

一句话分工：**本工具负责「不漏、可回填」；法律工作台负责「分析」。**

---

## 为什么必须在本机跑

法院实习接触的是未公开文书、当事人身份信息、部分书面证据。任何一次云端 API 调用都构成对外提供，且事后无法撤回。所以这条链路的设计前提是：

- **不联网**。除首次安装依赖外，运行期零网络请求。
- **原件只读**。程序从不修改输入文件。
- **真名隔离**。可交付的报告零真名；真名与代号的对照只存在加密映射表和一份单独打包的复核清单里。

## 三十秒上手

### 网页界面（推荐）

```bash
cd ~/mask-local
./mask-web
```

浏览器打开 <http://127.0.0.1:8765>，拖入文件、填案件名、选脱敏范围，点「开始脱敏」。

处理完有**两个下载包**，别搞混：

| 下载包 | 内容 | 能不能上传工作台 |
|---|---|---|
| 可交付包 | 脱敏件 + `脱敏报告.md` | ✅ 可以，零真名 |
| vault 包 | 加密映射表 + 密钥 + `复核清单.md` | ❌ 不行，含真实姓名 |

只监听 `127.0.0.1`，局域网和外部都访问不到。

### 命令行（批量、可脚本化）

```bash
cd ~/mask-local

# 一个案件一个文件夹，整包处理
./mask ~/案件材料/2024-民初-1234/

# 先只看会命中什么，不写任何文件
./mask ~/案件材料/2024-民初-1234/ --dry-run

# 单个文件
./mask ~/案件材料/起诉状.docx --out ~/脱敏输出/

# 环境自检
./mask doctor
```

> 已用 `pip install -e .` 装进 venv，也可以直接用 `mask-local` 命令，或 `.venv/bin/python -m masking.cli`。

### 分析完回填真名

```bash
./mask restore ~/脱敏输出/2024-民初-1234/民事判决书.docx \
  --vault ~/脱敏输出/2024-民初-1234/vault/2024-民初-1234.json \
  --out ~/回填_民事判决书.docx
```

回填件含真名，只留在本地，分析结束再打开。

### 网页端还原（适合编辑过的文件）

脱敏件交给工作台之后，你往往会在上面继续改——补句子、改表述、加段落。改完要还原真名时：

1. 打开 `decrypt.fragmerge.cn`，顶部切到「还原」
2. 上传**编辑后的脱敏件**
3. 上传当初下载的 **vault 包**（zip，里面是加密映射表与密钥）
4. 一键还原并下载

它只做两件事：把 `【代号】` 换回真名、把 `XXX1`/`XXX2` 换回证件号与电话。**其余文字一律不碰**，你改的、加的、删的都原样保留：

```
脱敏件    【熊猫】AAA【金鱼】
你改成    【熊猫】BBB【金鱼】
还原后    张三BBB李四
```

唯一失效的情形：编辑时把 `【】` 括号本身改掉了（比如删成「熊猫」）。映射表里只有完整代号，改坏的这处不会瞎猜，原样留着由你核对。

> 映射表丢了就再也换不回真名，这是单向的。`vault/` 目录务必单独备份。

### 手动补词（规则抓不到的名字）

规则能认身份证、能认「云南」，但认不出「阿某古某」这种姓氏表里没有的音译名。这类词由你直接指定：

```bash
./mask ~/案件材料/2024-民初-1234/ --terms "阿某古某,买某提·某"
```

- 逗号、顿号、分号、换行都能分隔
- 逐字命中即脱，**优先级最高**（高于人名/地名检测器，用户显式指定的词不会被抢走）
- 网页端对应「指定必脱词」文本框，一行一个

它适合三种用法：先由你圈定几个必脱词再交给自动化补齐；或者反过来，机器先脱一遍、你审完再把漏的补进去重跑。

### 多次脱密（续跑）

一次没脱干净、或者材料分批给，需要再跑一遍时，**必须带上上一轮的映射表**：

```bash
./mask ~/案件材料/2024-民初-1234/ \
  --vault ~/脱敏输出/2024-民初-1234/vault/2024-民初-1234.json \
  --terms "阿某古某" \
  --out ~/脱敏输出/2024-民初-1234-第2轮
```

不带 `--vault` 会新建一套映射，那么第一份映射表就作废了——第二次给「张三」分配的可能变成【长颈鹿】，而第一份里张三还是【熊猫】。

带 `--vault` 时：

| 行为 | 说明 |
| --- | --- |
| 已有实体 | 原样沿用原代号，绝不重新分配 |
| 新实体 | 从**未被占用**的词池里取，不会与上一轮撞号 |
| 掩码编号 | 从既有最大值续编，XXX1/XXX2 不会重号 |
| 输出映射表 | 旧条目 + 新条目**合并成一份**，可直接用于回填 |

网页端对应「已有映射表」上传项，传上次下载的 vault 包即可。

### 交付前再自查一遍

```bash
./mask audit ~/脱敏输出/2024-民初-1234/
```

> 文件管理器路径（WSL）：`\\wsl.localhost\Ubuntu\home\<用户名>\mask-local`
> WSL 内路径：`~/mask-local`

## 脱敏规则

| 类型 | 原文示例 | 替换为 | 说明 |
|---|---|---|---|
| 自然人 | 张三 | 【熊猫】 | 动物名池，全篇同一人同一代号 |
| 地名 | 杭州市、西湖区、文三路、江南大道 | 【昆仑】市、【蓬莱】区、【甘枣】路、【瀛洲】大道 | 山海经地名池，**保留行政区划后缀**，层级不丢 |
| 公司机构 | 杭州某某科技有限公司 | 【白桦】公司 | 植物名池，保留机构类型（公司/律师事务所/医院…） |
| 案号 | (2024)甲法民初1234号 | (2024)甲法民初1号 | 支持 `( )`/`（）`/`〔〕`/`[]` 四种括号；保留年份与案件类型，法院代字自编、序号重排 |
| 身份证 | 33010619900101123X | XXX1 | 全局唯一编号 |
| 手机号 | 13800138000 | XXX2 | 同上 |
| 统一社会信用代码 | 91330100MA2K7X8Y9R | XXX3 | 同上 |
| 银行卡 / 车牌 / 邮箱 | — | XXX4、XXX5… | 同上 |
| **金额、日期、法条、案由、裁判结果** | — | **不脱敏** | 法律分析必需；见「已知局限」 |

- `XXX1`、`XXX2`… 在**一个案件内全局唯一**，同一编号只对应一个原值，回填可精确到唯一原文。
- 代号里的【】是硬性约定：人眼和模型都能一眼看出这是脱敏痕迹，不会被当成当事人真名。
- 策略在 `config/rules.yaml`，词池在 `config/lexicon.yaml`，都能直接改。

## 输出结构

处理一个案件文件夹后：

```
2024-民初-1234/
├── 民事判决书.docx            脱敏件（保持原目录结构）
├── 证据清单.xlsx
├── 受理通知书.pdf             矢量保留，供人工核对/打印
├── 受理通知书.txt             ← PDF 伴生纯文本，给工作台读
├── 送达回证_扫描件.pdf
├── 送达回证_扫描件.txt
├── 脱敏报告.md                零真名，可交付
└── vault/                     ⚠ 不可交付
    ├── 2024-民初-1234.json    加密映射表（0600）
    ├── .key                   密钥（0600）
    └── 复核清单.md            含真名（0600），首行有警告
```

### 为什么 PDF 要配一个 `.txt`

脱敏时 PDF 的文本层被重写，代号是追加写入的，所以**默认 `get_text()` 会把代号排在页尾**，正文位置变空洞：

```
默认提取：'原告：\n，男，1990 年1 月1 日出生…'      ← 人名叫在页尾，顺序错乱
伴生 txt：'原告：【长颈鹿】，男，1990 年1 月1 日出生…'  ← 正确
```

所以每个脱敏 PDF 都导出一份同名 `.txt`，内容取自 `get_text(sort=True)`，页间用 `\f` 分隔。**给法律工作台分析时用 `.txt`，PDF 留着人工核对。**

### 报告里的三张清单

1. **已处理** — 每个文件替换多少处、按类型统计
2. **需人工复核** — 低置信度命中（尤其姓名）、图片内容、代号放不下的位置、残留扫描命中
3. **无法处理** — 加密 PDF、OCR 失败页、不支持格式

## 它替你堵住的泄露点

这些位置改正文改不到，程序逐项处理：

| 位置 | 风险 | 处理 |
|---|---|---|
| docx 修订记录 `w:ins`/`w:delText` | 修订里留着被删掉的原文 | 应用前整体接受修订 |
| docx 批注 + 作者 | 承办法官意见、批注人姓名 | 批注内容脱敏保留（分析有用），报告告警建议对外前人工删 |
| docx/xlsx 文档属性 | 作者、最后修改人、公司 | 清空；title/subject 保留脱敏值 |
| docx 段内换行 `<w:br/>`、`<w:tab/>` | 替换后换行位置漂移 | 按节点序列重建，换行/制表符/分页符位置不变 |
| xlsx 隐藏行列 | 身份证、内部备注常藏在隐藏列 | 隐藏行列照常处理 |
| xlsx sheet 名、定义名称 | sheet 名可能就叫「张三证据清单」 | 提取为文本块参与脱敏 |
| PDF 元数据 / 注释 / 书签 / 内嵌文件 | 作者、批注人 | 审计并清理 |
| PDF 扫描件 | 无文本层，改字改不到 | OCR 后按坐标真实擦除像素 |

**PDF 不是画黑框**：用 `apply_redactions(images=PDF_REDACT_IMAGE_PIXELS)` 真正删除底下的文字与图像像素，再写入带框代号。扫描件还会做一次「擦除后重新 OCR」复核，确认像素里也没原文。

## 已知局限（请认真看）

1. **中文姓名无法 100% 覆盖。** 姓名没有校验位，靠姓氏表 + 上下文线索推断。实测局限：单姓 4 字名会截断（欧阳某玺 → 易烊千）、少数民族音译名可能只命中后半段（阿某古某 → 古丽）、「原告王某平」这类含连接字的姓名只给 0.5 低置信度。**报告里「需人工复核」清单必须自己过一遍。**
2. **扫描件 OCR 有错字。** 模糊、倾斜、印章遮挡会导致识别错误 → 该处漏检。扫描件务必看复核清单。
3. **图片里的信息脱不了。** 证件照、印章、手写签名、截图粘贴——只能检测到并**强制**进复核清单，不能识别内容。要手工遮盖。
4. **日期与金额默认保留。** 刻意为之：脱掉后分析不出利息、违约金、诉讼时效。代价是极端情况下「某日 + 极小众事实」仍可能反推个案，报告里单列了这项风险。
5. **文件名与目录名不脱敏。** 若文件名含当事人姓名（`张三起诉状.docx`），交付前请自己改名。
6. **PDF 回填是尽力而为。** 能还原文字，版式可能与原件不同；重要文书建议用原件改名的方式回填。
7. **老格式 `.doc` / `.xls` 需先转换。** 本工具只认 `.docx` / `.xlsx` / `.pdf` / `.txt`；`.doc`/`.xls` 先用 LibreOffice 另存（转换会改排版，原件留着）。

## 词池用尽怎么办

一个案件超过 **117 个自然人、189 个地名或 97 个机构**时，程序会**报错停下**，不会循环复用代号——复用会让两个不同主体拿到同一代号，法律分析会数错当事人。按报错提示往 `config/lexicon.yaml` 对应池子加词，重跑即可。

## 免责

本工具是脱敏**辅助**，不是脱敏**保证**。交付前请务必：

1. 打开「需人工复核」清单逐条看过
2. 对关键文书的脱敏件做肉眼比对
3. 上传工作台时**只传可交付包**，`vault/` 留在本地
4. 确认批注、图片内容、文件名都已处理

它把「逐份手工遮盖」变成「自动处理 + 重点复核」，不能替代你的判断。
